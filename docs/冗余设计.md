### 1. BaseAgent ABC 仅有一个实现

- **位置**: `src/athena/core/agent/agent.py:80-95`
- **类型**: 不必要的抽象层（只有一个实现的 ABC）
- **描述**: `BaseAgent` 是抽象基类，定义了 `name`、`description` 属性和 `run()`、`tool()` 方法。但整个代码库中只存在一个具体实现：`Agent`（第 98 行）。`BaseAgent` 没有提供任何共享逻辑，仅仅声明了契约——这个契约完全可以通过 `Agent` 自身的接口来实现。`agent_runner()` 适配器（第 327 行）的类型标注是 `BaseAgent`，但实际上也只会收到 `Agent` 实例。
- **建议**: 删除 `BaseAgent`，将 `name`/`description`/`run`/`tool` 直接作为 `Agent` 的公开接口。`agent_runner()` 的类型标注改为 `Agent`。

### 2. create_code_agent 薄包装函数

- **位置**: `src/athena/core/agent/agent.py:378-384`
- **类型**: 不必要的间接层（A -> B -> C，B 不做逻辑）
- **描述**: `create_code_agent(model, tools, system_prompt, config)` 的实现只有一行：`return Agent(model, tools, system_prompt, config)`。它不加任何验证、转换或默认值，仅仅转发参数。调用方完全可以写 `Agent(...)` 替代 `create_code_agent(...)`。
- **建议**: 删除 `create_code_agent`，让调用方直接使用 `Agent(...)` 构造函数。

### 3. evaluation/types.py 纯再导出

- **位置**: `src/athena/evaluation/types.py:1-6`
- **类型**: 不必要的间接层
- **描述**: 整个文件只是从 `athena.core.schemas` 再导出 `ComparisonVerdict`、`EvalResult`、`EvalSpec`、`MetricDef`。这四个类型在 `core.schemas` 中已有定义，`evaluation/types.py` 不添加任何自有类型、不包装、不转换。下游模块（`factory.py`、`comparator.py`、`evaluator.py`）用 `from athena.evaluation.types import ...` 实际拿到的是 `core.schemas` 的类型。
- **建议**: 删除 `evaluation/types.py`，让依赖方直接从 `athena.core.schemas` 导入。

### 4. core/evaluation.py 废弃再导出

- **位置**: `src/athena/core/evaluation.py:1-3`

- **描述**: 文件开头注释 "Deprecated: import from athena.evaluation instead"，内容仅为从 `athena.evaluation` 再导出 `Evaluator` 和 `Comparator`。目前 2 个调用点（`workflows/search/search_loop.py` 和 `experiment/search_loop.py`）仍引用此废弃路径。

### 5. 双份 EvaluatorFactory

- **位置**: `src/athena/workflows/prepare/evaluator_factory.py:21-42` 和 `src/athena/evaluation/factory.py:22-80`
- **类型**: 重复逻辑
- **描述**: 两个模块各有一套 `EvaluatorFactory` 类，功能高度重叠——都是根据 `task_type` 查找默认指标并构建 `EvalSpec`。区别仅在于 API 风格（一个是 `@staticmethod`，一个是实例方法 `build()` + `freeze()`）和次要指标的丰富程度。核心逻辑完全重复。
- **建议**: 合并为一个 `EvaluatorFactory`，放在 `athena.evaluation` 下，删除 `workflows/prepare/evaluator_factory.py`。

### 6. freeze() 方法无实际效果

- **位置**: `src/athena/evaluation/factory.py:43-46` 和 `src/athena/workflows/prepare/evaluator_factory.py:40-42`
- **类型**: 过度工程 / 伪安全措施
- **描述**:
  - `evaluation/factory.py` 的 `freeze()` 只是 `return self._spec`，加了一句 "build() 必须先调用" 的检查。返回的 `EvalSpec` 仍然是可变的（Pydantic `model_config = {"frozen": True}` 已经提供了不可变性），"freeze" 语义完全由 Pydantic 的 `frozen=True` 保证，不需要额外方法。
  - `workflows/prepare/evaluator_factory.py` 的 `freeze(spec)` 是静态方法，直接 `return spec`，完全不做任何处理。注释说 "不可变性由约定保证" 更是表明了这是多余的。
- **建议**: 删除两个 `freeze()` 方法。Pydantic 的 `model_config = {"frozen": True}` 已经保证了不可变性。

### 7. Comparator 类过度工程化

- **位置**: `src/athena/evaluation/comparator.py:5-15`
- **类型**: 过度工程（简单函数封装为类）
- **描述**: `Comparator.compare(baseline, candidate)` 只是做了一行算术：`delta = candidate.primary - baseline.primary`，然后根据 delta 的正负返回 `ComparisonVerdict`。没有任何状态、不需要依赖注入、不需要实例化。5 行的纯函数包装成了带 `__init__` 的类。
- **建议**: 改为模块级函数 `compare_results(baseline, candidate) -> ComparisonVerdict`，删除 `Comparator` 类。

### 8. Brainstorm 包装层已删除

- **位置**: `athena.ideator.Ideator`
- **状态**: 已解决
- **描述**: 旧 `athena.brainstorm` package、`HypothesisInput`、`BrainStormResult` 及相关 wrapper 已全部删除，不保留兼容导出或模板 fallback。
- **最终契约**: `Ideator.generate()` 返回包含 hypotheses、transcript、failures 与 audit artifact 的 `DebateResult`。IdeaGeneration 消费该结果，登记并仅返回原样 hypotheses 列表；每个 hypothesis 的 parent id 与 `evidence_refs` 均不改写，其中 `evidence_refs` 保留 audit 引用。

### 9. ServerRequestReply 重复定义

- **位置**: `src/athena/app_server/protocol.py:156-159` (ProtocolModel) 和 `src/athena/app_server/transport.py:124-138` (plain dataclass)
- **类型**: 重复数据结构
- **描述**: `ServerRequestReply` 在两个模块中分别定义了不兼容的版本：
  - `protocol.py` 中是 Pydantic `ProtocolModel`（frozen + forbid extra），包含 `server_call_id`、`result`、`error` 三个字段。
  - `transport.py` 中是普通 Python 类，使用 `__init__` 手动管理字段，包含 `server_call_id`、`result`、`error_code`、`error_message`。
  - 实际使用时，`client.py` 从 `transport.py` 导入并手动传 `error_code`/`error_message`，而 `server.py` 从 `transport.py` 导入用 `isinstance` 判断。
- **建议**: 统一为一个定义（建议按 `protocol.py` 的 `ProtocolModel` 版本），删除 `transport.py` 中的重复定义。

### 21. GUI Gateway WebSocket Transport 冗余错误捕获

- **位置**: `src/gui_gateway/transport.py`
- **类型**: 过度复杂的错误处理（catch 后重新构造）
- **描述**: `WebSocketTransport.handle()` 中 `except Exception as exc:` 捕获所有异常后手动构造 `ResponseEnvelope(request_id=0, result=None, error={"code": -1, "message": str(exc)})`，然后通过 WebSocket 发送。这个错误格式 (`{"code": -1, "message": ...}`) 绕过了 `protocol.py` 中已有的 `RpcError` 和 `rpc_error()` 工具函数。
- **建议**: 使用 `rpc_error(ErrorCode.INTERNAL, str(exc))` 统一错误构造。
