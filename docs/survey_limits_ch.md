# 文献调研：交付什么、代价多少、边界在哪

`--survey` 是一个默认关闭、开启后要花十几到几十分钟模型往返的能力。这份文档回答三个问题：
**它到底交付了什么、代价是多少、以及它在哪里停下**。

前两个问题此前分散在各处，第三个问题——"开了它假设会不会更好"——从 2026-08-16 起挂了两次
（[语料接入](corpus_ideation_ch.md) 第六节、[链路整改](survey_overhaul_ch.md) 六点九），
2026-08-18 第一次答出来了。答案是：**在实测的那个任务上没有，而且两个可机械测量的指标显著变差**。

> 这不是"调研无用"的一般结论。是"在这条链路当前的形态下、在那一类任务上，调研的产出到不了
> 假设里"的一次可复现的观测。差别很重要，第四节逐条写清楚。

## 一、它是什么

四段流水线 `paper_scout` → `paper_source` → `paper_markdown` → `paper_rag`，由
`research/literature/survey/pipeline.py` 驱动、`research/literature/survey/wiring.py` 装配，产出一个 `corpus_ref`。Ideator 与
PlanAgent 拿到只读检索算子，可以搜、可以打开正文；假设里的 `sources` 要经三层核验。

接口、环境变量、降级行为见 [Academic Survey 全链路](academic_survey_ch.md)；
接入 loop 的四条约束与引用核验见 [文献语料接入 loop](corpus_ideation_ch.md)。
本文不重复那些，只讲代价与边界。

## 二、代价

### 一次完整调研的分阶段耗时

2026-08-18 实测，20 篇入库，独立跑（`Athena-cli survey`）：

| 阶段 | 秒 | 占比 |
|---|---|---|
| markdown 转换 | 178.9 | 46.1% |
| 取源 | 155.3 | 40.1% |
| 索引 | 52.7 | 13.6% |
| scout | 0.0 | 命中缓存 |
| 合计 | 387.8 | |

这一轮 scout 为 0 是因为命中了同一条 query 在臂内那次运行留下的缓存。**冷启动完全不是这个
数量级**：同一条 query 在臂内那次实测 scout 392 秒（6 步、池 201 篇）、取源到 1078 秒，
19 分钟内没跑完转换。

### scout 内部：打分是压倒性的大头

2026-08-18 的分段计时（`--fresh-scout`，池 312 篇）：

| 类别 | 次数 | 忙时 | 每次 | 占 scout 墙钟 |
|---|---|---|---|---|
| **打分** | 28 | **803.0s** | 28.68s | **58.4%** |
| 后端检索 | 44 | 338.8s | 7.70s | 24.7% |
| 策略 | 6 | 110.9s | 18.49s | 8.1% |
| 同分排序 | 21 | 69.0s | 3.29s | 5.0% |
| 合计忙时 | | 1321.8s | | **96.2%** |

打分占 scout 的 58.4%，而 scout 占全程 68.6%——**打分一项就是整次调研的 40%**。
`DEFAULT_BATCH_SIZE` 是 24，而 28 次调用摊 312 篇只有每次 11 篇：批次被动作边界切碎了。
跨动作攒批能把调用数从 28 压到约 13，但会让策略模型在 observation 里看到未打分的论文——
未实施，见 [整改](survey_overhaul_ch.md) 六点十二。

### 方差比想象中大

同一条 query 三轮，scout 墙钟 631 / 881 / 937 秒，而第三轮动作数反而最少。
交付集合的两两 Jaccard 只有 0.114 / 0.111 / 0.345，远低于离线固定池子时测到的 0.69–0.79。

**主要矛盾在检索的可复现性上，不在打分。** 离线实验固定池子只让打分抖动；真机三轮的池子是
352 / 244 / 188。同分次序那项改进（把 0.690 抬到 0.791）解决的是次要矛盾。

### 忙时与墙钟是两个数

调研是与 SEARCH 并行的后台任务，它的秒数不占关键路径；各 plan 的活跃区间可以互相重叠。
把它们相加算占比会得到超过 100% 的数——本文所有表格都标明了是"墙钟划分"还是"可重叠区间"。

## 三、交付：语料对假设的实际影响

### 实验设计（2026-08-18）

数据集本地生成（网络取不到公开数据集，OpenML 实测 90 秒超时），60000 行 / 正类 6.32%，
按已知生成过程构造，因此**留出集上的贝叶斯最优 AP 可以精确算出 = 0.3828**。
train 48000 行带标签、test 12000 行标签物理抽走、答案键单独一个目录。
PREPARE 基线 AP = 0.29952。

两层：

| | 端到端两臂 | 只跑 ideation |
|---|---|---|
| 变量 | `--survey` 开/关 | `state.corpus_ref` 有/无 |
| 共用 | 同一 PREPARE 分叉：冻结 evaluator、基线 commit | 同一项目、同一 EDA |
| N | 每臂 6 次实验 | 每臂 4 轮 × 6 条 |

### 主结果：ideation 层

同一个项目、同一份 EDA、同一个模型，只切换 `corpus_ref`。每轮开跑前有硬前置检查，语料解析
不到就当场报错——8 轮全部打印"语料就绪：20 篇"。

| 指标 | 开调研 | 关调研 | p |
|---|---|---|---|
| 存活假设总数 | 13 | 23 | — |
| 每轮存活假设 | 3, 4, 3, 3 | 5, 6, 6, 6 | **0.011** |
| 轮内两两词重合（低=多样） | 0.406 | 0.192 | **0.014** |
| 每轮耗时 | 1009 s | 271 s | — |
| 每轮触及的方法类别 | 5.50 | 6.50 | — |
| 干预里的具体数值 | 0.52 | 0.84 | — |
| 带引用的假设 | **0 / 13** | 0 / 23 | — |

两个显著指标都达到了 n=4 能达到的**最强显著性**——每一个开调研轮次都比每一个关调研轮次差，
没有交叠，p=0.011 与 p=0.014 已是这个样本量下的下限。

### 语料被读了，只是没进到假设里

| 环节 | 计数 |
|---|---|
| `paper_chunk_read` | 143 |
| `paper_corpus_overview` | 50 |
| `paper_search` | 4 |
| 草稿里发出的引用 | 42 |
| 其中指向真正打开过的论文 | 32（76%） |
| **最终假设里存活的引用** | **0** |

剔除发生在第三层 `_verify_support`（"这段正文到底支不支持这条主张"，判据刻意保守）。
用一个零模型调用的探针确认账本工作正常：`paper_chunk_read` 之后 `corpus_papers_read()`
如实记录，所以不是账本的问题。

**而这一层大概率是对的。** 那些假设是"删掉这个数据集的 10 个噪声列""加
debt_ratio × utilization 交互"——不平衡学习的论文确实支持不了它们。
也就是说：**Ideator 读了论文，但想法来自 EDA；引用是事后贴上去的，被核验如实剥掉。**

最说明问题的一个细节：语料是 20 篇不平衡学习的论文，而两臂 36 条假设里**没有任何一条提出过
重采样**（SMOTE / ADASYN / 欠采样）。开调研那臂读了 143 个 chunk，提的仍然是特征选择与梯度提升。

### 端到端那一层没测到调研

两臂都从同一个 PREPARE 分叉，各跑 6 次实验。结果是**开调研臂的 `corpus_ref` 到最后仍是
`None`**——它不是实验臂，是对照条件的第二次独立运行。

| 指标 | arm_nosurvey | arm_survey |
|---|---|---|
| SEARCH 墙钟 | 3566 s（59.4 分） | 1022 s（17.0 分） |
| 假设 / ideation 轮 | 11 / 2 | 6 / 1 |
| 实验（失败） | 6（2） | 6（0） |
| 预测逐字相同的空转 | 2 | 2 |
| 最好 AP | 0.310764 | 0.304924 |
| 相对基线 | +0.011244 | +0.005404 |
| 语料 | 无 | **无（赛跑输了）** |

这一对因此不是 A/B，但它给出一个比任何单臂分数都有用的量：**同条件两次独立运行的 best-AP
相差 0.0058**。这是噪声地板——任何小于它的调研效应，在每臂 N=1 下不可测。

**为什么调研必输**：`_start_survey` 的设计前提是"调研与 PREPARE 并行，PREPARE 也不快"。
但**分叉臂跳过 PREPARE**——那段掩护时间没了，调研与 SEARCH 同时起跑：

```
SEARCH 结束        1022 s   6 次实验跑完
进程退出           1145 s   VALIDATE 失败
调研被取消时        转换阶段   scout 完成 392 s，取源完成 1078 s
```

这是 fork 与 survey 两个功能的**交互**缺陷，只在"用 fork 做 A/B"时出现——而那正是这两个功能
唯一被设计来一起用的场景。**未修复**，可能的修法见第九节第 1 条。

### 评判器：先标定，再决定要不要用

盲对比的评判者与提出者出自同一族模型，先验上不可信。先让它在**有真实 AP 的 42 对**上表态：
判出胜负 36 对，与真实 AP 方向一致 25 对 → 一致率 **69.4%**（p = 0.014）。带真信号，但离可靠
很远。

它在 13 对盲对比上的判决是关调研胜 6、开调研胜 2、平或自相矛盾 5，**p = 0.289，与随机不可
区分**——方向与机械指标一致，但只作旁证，不当结论。

## 四、限制清单

### 4.1 这次测量本身的限制

- **单一任务、单一数据集、单一检索式。** 换一个文献与干预结合更紧的任务（损失函数设计、
  特定架构的超参区间），结果可能相反。本任务的最优解是特征工程与缺失处理，那是 EDA 的地盘
  不是论文的地盘——语料再好也插不上手。
- **每臂 4 轮。** p=0.011/0.014 已是 n=4 的下限，再小的 p 需要更多轮。
- **端到端那层没有测到调研**，它给出的是噪声地板（0.0058），不是效应量。
- **评判器不显著**（p=0.289），6:2 的方向不能当证据。
- **数据集是本地生成的。** 好处是贝叶斯上界可精确计算；代价是真实数据的结构更复杂。
- **三个阻断性缺陷刚修完就跑了实验，没有复现。**

### 4.2 链路的结构性限制

- **调研赶不上 SEARCH。** 冷启动一次调研 19 分钟跑不完，而 6 次实验的 SEARCH 可以 17 分钟
  结束。分叉臂没有 PREPARE 掩护时，调研必然赶不上；进程退出会把它连带取消，**成本全付、
  产出为零**。
- **`_verify_support` 会剥掉与假设无关的引用，这是对的**，但它同时意味着：只要 Ideator 的
  想法来自 EDA，语料读得再多也不会在 `sources` 里留下痕迹。**"0 引用"不能读成"没读语料"。**
- **单篇论文的编码代价没有上限。** SMOTE 那篇（`arxiv:1106.1813`）TeX 入口推断失败，转换器
  把整包连成 77 万字符、35151 句，一篇占整个语料 66%，建索引 3259 秒、占那次全程的 47%。
  碎片闸门（`SHRED_MIN_SENTENCE_CHARS=40` / `SHRED_MIN_SENTENCES=200`）后来拦住了它，
  但**闸门判的是内容对不对，不判代价**——没有任何东西限制单篇论文能贡献多少编码量。
- **检索的方差没有常设测量。** 交付集合跨轮 Jaccard 0.111–0.345，而池子规模在 188–352 之间
  漂。这是最大的不可复现来源，目前没有任何常设指标盯着它。
- **`ATHENA_CONTACT_EMAIL` 未设置**，因此不进 arXiv / OpenAlex 的礼貌池，限速更紧。
- **arXiv 是取源的地板。** `HostRateLimiter` 对 `arxiv.org` 强制 3 秒最小间隔（上游明文要求），
  这一段按设计就该串行。分波并发只压得动出版商那一半：受控对照实测 408.7 → 342.4 秒，
  **1.19×**，不是先前预估的 10%。

### 4.3 已知会静默失效的地方

这一类最危险：不报错，只是结果没有意义。

- **语料解析不到时 `corpus_tools` 返回 `None`**，Ideator 就退化成没有语料的那一臂，两臂看起来
  都正常。本次实验为此加了硬前置检查（解析不到当场报错）——但那是在实验脚本里，不在产品里。
- **`context_refs` 是一条死信道**：到模型那里只剩 sha256，通用工具集里没有按 ref 取正文的算子。
  `handoff_block` 的文档字符串写过这条教训，而假设本身漏掉了整整一轮（见第五节）。
- **fixture 与真实序列化形状不符**会让单元测试整体失去意义。`fork_project` 的 15 条用例全绿，
  而被测函数在产品真正写出来的 `research_tree.json` 上一次都没跑通过。
- **`_verify_sources` 的剔除只发一条 error 输出**，没有订阅者时无声无息。本次是靠比对 rollout
  日志才知道 42 条引用被剥光的。
- **金标是代理。** `bench recall` 的 83 篇来自"目前跑过的最强配置判为 ≥0.45"的那一批，它回答的
  是 R@all（更便宜的配置能捞回多少），**不能回答"到底存在多少"**。

## 五、为让这个实验成立而修掉的三个缺陷

三个都是"失败信息指向的地方和真正的原因隔着一层"。都已提交并带上会在缺陷复现时变红的用例。

| commit | 缺陷 | 表现 |
|---|---|---|
| `047f379` | 分叉不带 EDA 工作区 | 每个 Ideator lane 抛 "EDA workspace is stale"，异常被吞成 error 输出 → **这一臂没有假设** |
| `18f4d5e` | 分叉按 `experiment["kind"]` 找基线，而 `kind` 在 `plan` 里 | 对刚跑完 PREPARE 的项目分叉 → **"source project has no baseline experiment"**，即 `fork_project` 在真项目上从未成功过一次 |
| `eeabf9a` | 假设经 `context_refs` 传给 PlanAgent | **它从来没见过要实现什么** |

### 第三个的后果最重

修复前一条臂 6 次实验**无一实现分配给它的假设**：

| 实验 | 分配的假设 | 实际提交的代码 |
|---|---|---|
| 3 次 | — | 直接 `abandon`，理由逐字 "The user message does not contain explicit hypothesis text" |
| `e6676` | 加交互特征 | 删噪声列，代码里自带一行 `Hypothesis: Removing noise columns …` |
| `5ec57` | 用 IterativeImputer 替代中位数填充 | 删噪声列 + 交互特征 + log 变换，**没有 IterativeImputer** |
| `75047` | 删噪声列 | 删噪声列（碰巧撞上——那是看不见假设时的默认动作） |

两条不同的假设都退化成同一个默认动作，产出**逐字节相同的预测**（AP 均为 0.304924）。
修复后 PlanAgent 的第一句话变成 "I need to implement the hypothesis: removing noise columns…"，
与分配的假设逐字对应。

**这意味着在 2026-08-18 之前，SEARCH 从来没有真正执行过 Ideator 提出的假设。** 任何"假设质量
→ 下游分数"的实验，在这条信道修好之前都测不到自己以为在测的东西。

### 一条方法论教训

[语料接入](corpus_ideation_ch.md) 六点九专门为"会静默失败的那种"写了一条集成用例：构造一个
"PREPARE 已完成"的项目、分叉成两臂、断言两臂的 `(evaluator_ref, phase, corpus_ref, sota)`
逐字段相同。**它一直是绿的，而 `fork_project` 从未在真项目上成功过。** 原因是那条用例的
fixture 也按错误的形状造数据，而且从不创建 EDA 目录。

为"这类失败很安静"而写的测试，本身可以同样安静地失效。判据只有一条：**fixture 必须来自产品
真正写出来的东西**。

## 六、泄漏：为什么必须靠结构堵死

第一版把整份含标签的 60000 行交给 agent 自己划留出集。基线报了 **AP = 0.4110**，而那批留出行
上的**贝叶斯上界是 0.3682**——高出理论极限 0.043。查代码，`train_model.py:255` 写着
`# Now retrain each model on full data for final predictions`：它在含留出行的全量数据上重训
再预测，0.4110 是样本内分数。

**关键在于这不是失误。评估行的标签就在训练文件里时，"最后用全量重训"是标准好做法**，
所以泄漏是默认路径，而评估器只拿得到预测、看不见这件事。

检测器的容差按实测两端定，而不是拍一个 σ 倍数：

| 样本 | AP | 相对上界 |
|---|---|---|
| 样本内重训（历史泄漏） | 0.4110 | +2.4σ |
| 贝叶斯上界 | 0.3828 | 0 |
| 本轮最好的合法提交 | 0.3108 | −4.1σ |
| PREPARE 基线 | 0.29952 | −4.7σ |

第一版取 3σ（±0.0529）反而抓不住历史那次只超出 0.043 的泄漏；改成 1σ 后两端都对。
本轮 12 次实验无一越过上界。

## 八、SEARCH 的耗时：两个反直觉之处

**修好假设信道让 SEARCH 变慢了三倍，这是好事。** 修复前一条臂 6 次实验只要 19 分钟，修复后
同样 6 次要 59 分钟。原因很直接：agent 现在真的去做被要求的事（超参搜索、MICE 填充），而不是
每次都退回同一个廉价默认动作。**快是因为它没干活。**

**近七成墙钟可以被两次失败的实验吃掉。** `arm_nosurvey` 全程 3566 秒里：

| 去向（plan 活跃区间，可重叠） | 秒 | 占全程 |
|---|---|---|
| 两次超参调优（**均失败**） | 2468 | 69.2% |
| ideation（6 lane / 2 轮） | 887 | 24.9% |
| 四次成功的实验 | 363 | 10.2% |

Optuna 跑完但打分未落地。四次真正产出分数的实验加起来只占 10.2%。

## 九、如果要继续

1. **让调研跑在 SEARCH 之前，而不是并行。** 分叉臂没有 PREPARE 掩护，当前设计保证调研赶不上。
   要么先建语料再起 SEARCH，要么让 SEARCH 在第一轮 ideation 前等语料一次。
2. **换一个文献真正能给出干预细节的任务。** 本任务的最优解在 EDA 的地盘上，语料插不上手。
3. **把"引用被剥掉"单独观测。** 现在只知道最终 0 条，不知道 `_verify_support` 拒绝的理由分布。
   加一条把逐条判定落盘的开关，才能判断是核验太严还是引用确实无关。
4. **给检索方差加常设测量。** 它是目前最大的不可复现来源，而且没有任何指标盯着。
5. **给单篇论文的编码量设上限。** 碎片闸门判内容不判代价。
