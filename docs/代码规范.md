## 代码风格

对于所有的函数，变量等都需要写注释。

```python
class A():
    ...

t = A()
t:A =()

```

在写代码的时候，我们的每一个功能，每一个函数都需要有一个单元测试。
如果是模块，需要有详尽的输入输出，
函数的话，需要有一个简单的输入输出示例放在注释里面。
## 代码结构
代码嵌套不超过3个
不推荐：

if (user != null) {
    if (user.isActive()) {
        if (user.hasPermission()) {
            if(user.execute())
            {
                break;
            }
        }
    }
}

AI 不得无必要地引入复杂设计模式；多层封装；过度抽象；复杂继承；无实际用途的通用组件；不必要的新依赖。

能用简单代码清楚解决的问题，不应设计成复杂框架。
**同时引入框架中有的功能，不要重写**
减少 _开头的功能简单且用到次数少于2次的函数。使用这种函数会降低项目可读性


文件结构应该是
```text

导入的包


======  导入的包 ======

常量定义
变量定义

======

功能代码

```

## 异常处理

对于不必要的异常不应进行异常处理。
我们在代码逻辑中明确某个变量只可能出现某个类型的情况是，不要多此一举给出try catch捕获不可能出现的异常。
同时**异常处理应该是项目完成过后添加的。在初次写代码时添加会导致无法定义错误点**
