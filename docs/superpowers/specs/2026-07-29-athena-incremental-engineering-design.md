# Athena 兼容优先工程化设计

> 日期：2026-07-29
> 状态：已确认
> 范围：现有代码规范化改动、`docs/冗余设计.md` 所列问题及当前测试回归

## 1. 目标

本轮采用兼容优先的增量治理方式，在不破坏 Athena 现有公共接口和协议的前提下：

1. 修复规范化改动引入的 Python 导入回归。
2. 治理能够证明行为等价、具有测试覆盖的重复定义和内部冗余。
3. 保留仍被测试、示例或生产代码使用的公共入口。
4. 用完整 Python、前端和构建门禁证明改动没有引入行为退化。
5. 更新冗余设计记录，使每项问题具有明确处置状态。

## 2. 决策原则

- 正确性优先于形式合规。规范化改动不得使模块无法导入或改变运行时行为。
- 公共兼容入口与重复实现分开判断。薄重导出可以保留，但同一类型不得存在两个类体。
- 删除必须同时满足：无生产消费方、无公共导出承诺、无测试依赖，并可由静态扫描证明。
- 字段名、默认值、序列化格式、异常类型和事件协议保持不变。
- 不为未来需求新增抽象、包装类型或配置层。
- 每个行为修复和重构先建立能够失败的测试，再做最小实现。

## 3. 实施范围

### 3.1 门禁修复

`src/athena/ide/transport.py` 移除 `from __future__ import annotations` 后，`IDEHandler` 仍只在 `TYPE_CHECKING` 分支导入，运行时类定义会解析未加引号的类型名并抛出 `NameError`。

本轮将以模块导入测试锁定该行为，并把该注解改为字符串前向引用。随后扫描其他 `TYPE_CHECKING` 导入，确认没有相同模式。

### 3.2 低风险治理候选

以下条目可以进入逐项验证，但只有在静态消费方扫描和相关测试通过后才实施：

- 完全相同的类型类体统一为一个权威定义，旧路径仅重导出同一对象。
- 已有明确替代路径的内部废弃导入改为直接导入，兼容模块暂时保留。
- 未被生产代码、测试、示例或公共导出使用的内部占位符和死参数。
- 同一模块内可证明无状态、无扩展价值的私有包装层。
- 前端中未被入口或组件导入的重复全局样式，先核对实际样式规则再合并。

优先审计 `ExperimentOutcome`、`ServerRequestReply`、两套 `EvaluatorFactory`、重复 `AgentMonitor`、`TransportControl`、`StreamEmitter` 和 `App.css`/`styles.css`。审计结论可以是治理、兼容保留或暂缓，不以删除数量为目标。

### 3.3 本轮明确保留

下列对象仍存在直接测试、示例、公共导出或已确认设计依赖，本轮不删除：

- `BaseAgent`
- `create_code_agent`
- `Comparator`
- `athena.evaluation.types` 等仍承担兼容导入的模块
- ResearchTree v1、App Server、IDE RPC 和 Tauri 的既有协议结构

如果后续删除这些接口，必须另行完成消费者迁移、弃用策略和公共 API 评审。

## 4. 变更流程

每个候选项按以下顺序处理：

1. 使用 `rg` 确认定义、导出、生产调用、测试和示例引用。
2. 明确必须保持的类型身份、字段、返回值、异常和副作用。
3. 编写最小回归测试并确认它因当前问题正确失败。
4. 实施单一、最小的代码变更。
5. 运行目标测试和关联模块测试。
6. 若需要破坏公共导入或改变协议，则停止并把该项标记为暂缓。

不同领域的治理不捆绑为一次不可辨识的大改动。现有未提交规范化改动视为用户工作，不回退、不重写无关文件。

## 5. 错误与兼容性

- 类型注解必须在 Python 3.11 下可运行时求值；仅在 `TYPE_CHECKING` 导入的类型使用字符串前向引用。
- 兼容重导出必须用对象身份测试证明新旧导入路径指向同一对象。
- 协议模型不得把结构化错误退化为临时字典或改变序列化字段。
- 删除占位 API 前必须确认它没有被外部文档、示例和 package `__all__` 暴露；无法证明时保留并记录。
- 测试发现的新回归优先修复根因，不通过扩大异常捕获掩盖错误。

## 6. 验证门禁

最低验收矩阵为：

- `uv run pytest -q`
- `npm test -- --run`，工作目录为 `athena-ide`
- `npm run build`，工作目录为 `athena-ide`
- `git diff --check`

若改动涉及 Tauri 或 Rust，再追加对应的 `cargo fmt --check`、`cargo clippy` 和 `cargo test`。所有命令记录实际通过数量；未运行的门禁必须明确说明原因。

## 7. 文档结果

`docs/冗余设计.md` 保留原有问题描述，并为实际审计过的条目增加以下状态之一：

- `已治理`：重复实现已消除，兼容性和测试证据齐全。
- `兼容保留`：实现已统一，但旧入口作为公共兼容层保留。
- `暂缓`：删除会破坏公共 API、协议或缺乏足够验证。
- `误报`：静态审计证明条目并非冗余，并记录实际职责差异。

最终报告同时列出已修复回归、已治理条目、保留原因、测试结果和剩余风险。

- Python 测试不再在收集阶段失败，完整测试通过。
- 前端 20 个现有测试继续通过，生产构建成功。
- 本轮处理的重复类型只保留一个类体，兼容导入保持对象身份。
- 未删除仍被使用的公共接口，未改变协议和序列化合同。
- `docs/冗余设计.md` 的已审计条目具有可验证状态。
- 差异检查无空白错误，最终报告无未说明的验证缺口。
