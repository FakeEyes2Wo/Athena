# Athena GUI 全局视觉与布局升级设计

**日期：** 2026-08-14
**状态：** 已获用户逐段确认
**范围：** `athena-gui` 前端呈现层；不改变研究流程、Tauri bridge 或后端协议语义

## 1. 背景与目标

Athena 当前 GUI 已具备聊天、研究树、假设图、实验、EDA、LLM I/O、报告、设置等功能，但聊天页与面板页采用不同页面骨架，设计令牌与 CSS Modules 之间还存在重复规则。界面整体可用，但导航关系、信息层级、留白和组件状态缺乏统一，容易呈现为通用后台模板。

本次升级的目标是把整个 GUI 统一为专业、克制且高信息效率的“精密工作台”：

- 建立贯穿所有模块的统一 App Shell 与导航体系。
- 统一亮色、暗色主题下的色彩、排版、间距、圆角、边框和动效。
- 改善聊天、图表、表格、表单和状态反馈的视觉层级与可读性。
- 允许调整布局结构，但保留所有现有业务能力和数据流。
- 优先保证桌面端与约 1024px 以上窗口的使用体验。

## 2. 设计方向与取舍

### 2.1 已选视觉方向：精密工作台

采用冷灰中性色、白色内容面和亮蓝强调色。界面强调清晰网格、精准对齐和低噪声信息层级，接近成熟专业 SaaS/IDE，而不是强装饰性 AI 产品。

未采用的方向：

- 学术编辑感：辨识度高，但暖色纸张与展示性排版不适合全部高密度面板。
- 智能宇宙感：沉浸感强，但过度偏向暗色与氛围光效，长期数据工作可读性较弱。

### 2.2 已选布局方向：统一研究工作区

采用功能轨、上下文侧栏和主工作区组成的统一 App Shell。该方案比仅精修原结构更连贯，又避免四栏指挥中心长期挤占主画布。

未采用的方向：

- 原结构精修：回归风险低，但聊天页与面板页的割裂仍然存在。
- 四栏指挥中心：信息密度最高，但小窗口体验、改造成本和维护复杂度均过高。

## 3. 信息架构与整体布局

### 3.1 统一 App Shell

所有主模块共享以下页面骨架：

1. **顶部栏（约 52px）**
   - 展示 Athena 品牌、当前工作区和全局运行状态。
   - 承载主题切换、必要快捷操作和全局反馈入口。
   - 不重复页面级标题和模块工具栏。

2. **功能轨（约 48px）**
   - 提供会话、研究树、实验、数据分析、模型轨迹和报告入口。
   - 设置入口固定在底部。
   - 使用 Lucide 图标、工具提示和明确的当前项状态。

3. **上下文侧栏（约 232px）**
   - 内容随当前模块切换。
   - 会话模块显示工作区、新建会话和历史会话。
   - 面板模块显示局部导航、筛选和快捷入口。
   - 支持折叠；折叠状态属于前端呈现状态。

4. **主工作区**
   - 聊天内容采用约 840–900px 的阅读宽度并居中。
   - 研究树、图表、表格与报告使用可用完整宽度。
   - 各模块复用页面标题、说明、操作区和内容区结构。

5. **上下文抽屉**
   - 原有右侧摘要与详情能力迁移为按需打开、可关闭的抽屉。
   - 抽屉不长期挤占主工作区，不作为第四个常驻栏。

### 3.2 响应式规则

- 宽屏：功能轨、上下文侧栏和主工作区同时显示。
- 中等桌面窗口：优先折叠上下文侧栏，保留功能轨。
- 约 1024px 窗口：功能轨保持图标导航，主内容确保最小可操作宽度。
- 本次不以移动端为主要目标，但不得产生不可恢复的横向溢出。

## 4. 视觉系统

### 4.1 色彩

- 亮色主题使用冷灰页面背景、白色主内容面、深蓝灰正文和亮蓝主色。
- 暗色主题使用深蓝黑页面背景与分层表面，避免纯黑大面积铺底。
- 成功、警告、错误和信息色仅表达语义状态，不作为普通装饰。
- 大面积渐变和玻璃模糊不进入基础组件；品牌标记可使用极轻微强调效果。
- 所有文本、控件和状态色满足可读性与焦点可见性要求。

### 4.2 排版

- 正文字体使用 Geist；代码、路径、指标和结构化数值使用 Geist Mono。
- 常规正文以 14px 为主，辅助信息 12px，页面标题 20–24px，关键指标 24–32px。
- 页面标题、区块标题、标签、正文和辅助文字形成固定层级。
- 中文正文采用舒适行高；表格与指标优先对齐，避免因数字宽度造成跳动。
- 长路径、标识符与说明文本使用一致的截断、换行和展开策略。

### 4.3 间距、圆角与阴影

- 间距采用 4/8/12/16/24/32px 阶梯。
- 圆角收敛为 8px、10px、12px 三档。
- 大部分层级依靠背景、留白和细边框建立。
- 阴影仅用于抽屉、弹层、悬浮控件和必要的抬升状态。
- 同一区域避免多层卡片嵌套；优先使用区块标题、分隔线和留白分组。

### 4.4 交互状态与动效

- 按钮、导航、输入框、表格行和图节点具备统一的默认、悬停、按下、选中、禁用、加载和焦点状态。
- 动效短促克制，用于侧栏收放、抽屉、页面内容切换和状态反馈。
- 遵守 `prefers-reduced-motion`，减少动态效果时取消非必要动画。
- 键盘操作具有清晰的 `:focus-visible` 反馈。

## 5. 核心模块设计

### 5.1 聊天与会话

- 欢迎区以明确任务入口为核心，示例提示采用两列轻量操作卡片。
- 消息按角色、时间、工具调用和运行状态建立稳定层级。
- 工具输入输出继续支持折叠，但减少多余边框和高饱和背景。
- Composer 固定在主阅读列底部，整合输入、发送、停止和快捷提示。
- 会话侧栏突出当前工作区、新建会话和当前会话状态；历史会话使用列表而非卡片堆叠。

### 5.2 研究树与假设图

- 页面标题区统一承载视图切换、筛选、图例和必要操作。
- 画布最大化利用主工作区，不用常驻右栏缩小可视范围。
- 图节点重点展示状态、关键指标和 SOTA 标记；次要元数据进入详情抽屉。
- 画布工具、缩放和空状态使用统一控件样式。

### 5.3 实验、指标与时间线

- 页面顶部只展示少量关键指标，避免把所有统计都卡片化。
- 实验列表使用稳定的表格或时间线布局，统一状态徽标和数值对齐。
- 选中实验后在上下文抽屉显示详情与合法操作。
- 危险或不可逆操作提供明确确认与结果反馈。

### 5.4 EDA、LLM I/O、报告与设置

- 复用统一的页面标题、工具栏、分区标题、表单字段、表格和空状态。
- EDA 图表使用一致的色板、网格、轴文本和工具提示。
- LLM I/O 保留时间线与代码内容的等宽排版，增强角色和工具调用辨识度。
- 报告使用清晰的摘要、指标、章节与产物入口，不把正文切成过多小卡片。
- 设置表单按语义分区，标签、说明、校验信息和只读状态对齐。

## 6. 前端架构与数据流

- 统一布局落在共享 App Shell 中，各业务模块作为主工作区内容切换。
- 保留现有 `usePipeline`、Tauri bridge、事件订阅、RPC 和后端协议。
- 页面切换、侧栏折叠、抽屉开关和主题属于前端界面状态。
- 研究树、实验、指标、消息和设置仍由现有 hooks 与 bridge 提供。
- 视觉改造不得改变命令名、事件结构、业务状态机或持久化语义。
- 建立少量共享呈现组件：页面标题、工具栏、按钮、徽标、空状态、表单字段、指标展示和抽屉。
- 继续使用 CSS Modules；扩充全局设计令牌，并清理 `styles.css` 中与模块样式重复或冲突的旧规则。

## 7. 加载、空状态与错误处理

- 局部数据加载使用骨架、占位或局部进度，不触发整页闪烁。
- 空状态说明当前缺少什么、为何为空以及用户可采取的下一步。
- 请求错误显示在对应模块内，保留诊断文本并提供可用时的重试入口。
- 全局连接或运行状态在顶部栏显示，但不替代模块内的具体反馈。
- 表单校验信息紧邻字段；保存成功或失败提供明确反馈。
- 未知或意外错误不得破坏统一 Shell，主导航仍应可用。

## 8. 无障碍要求

- 所有图标按钮提供可访问名称和工具提示。
- 导航、抽屉、表单、表格和可折叠内容支持键盘操作。
- 焦点顺序与视觉顺序一致。
- 状态不能只依赖颜色表达，需结合文本、图标或形状。
- 亮色与暗色主题均保持足够文本、边框和焦点对比度。

## 9. 验收标准

1. 聊天、研究树、假设图、实验、EDA、LLM I/O、报告和设置入口共享统一 App Shell 与导航状态。
2. 聊天阅读宽度、全宽面板和按需详情抽屉符合本设计的布局规则。
3. 亮色与暗色主题下不存在明显不可读文本、状态混淆或层级丢失。
4. 约 1024px、1440px 和宽屏窗口下布局稳定，侧栏按规则折叠且无关键控件丢失。
5. 按钮、导航、表单、表格行、图节点和抽屉具备完整交互状态。
6. 键盘焦点、语义标签与减少动态效果支持完整。
7. 现有前端组件测试继续通过，并增加统一 Shell、模块导航、侧栏折叠和标准状态组件测试。
8. TypeScript 构建与前端测试通过，且不引入后端协议或研究流程行为变化。

## 10. 非目标

- 不重新设计或修改后端研究算法、Agent 行为与事件协议。
- 不为移动端建立独立导航或完整响应式产品体验。
- 不引入新的图表框架、路由框架或大型 UI 组件库。
- 不以高强度渐变、玻璃拟态或持续动画作为视觉主语言。
- 不在本次视觉升级中新增与现有 GUI 无关的业务功能。
