# Athena IDE 科研编辑部视觉重构设计

> 日期：2026-07-29
> 状态：设计已确认，待实施规划
> 视觉方向：A2.2「窄墨书脊」
> 实施路径：组件级视觉重构

## 1. 目标

将 Athena IDE 从通用浅色卡片界面重构为具有明确科研辨识度的对话工作台。新界面需要同时满足两个首要场景：

1. 挑战杯答辩、演示与截图中具有稳定的品牌记忆点。
2. 桌面端长期科研使用时保持低噪声、易扫描和低心智负担。

本次允许调整前端组件结构、布局、样式与界面文案，但保持现有业务数据流、Tauri bridge、WebSocket 事件和后端协议不变。

## 2. 已确认决策

- 保留“会话主区 + 右侧研究摘要 + 按需展开详情”的信息架构。
- 采用 A2「实验台账」结构，并选择 A2.2 的色调处理：保留墨绿，但取消深色顶栏并缩小深色面积。
- 使用组件级视觉重构，不止修改 CSS Token，也不扩展到工作区交互系统重建。
- 优先兼顾答辩展示与长期使用，不以单一截图效果牺牲操作效率。
- 用户可见的任务状态收敛为四种，减少标签、颜色与重复反馈。

## 3. 非目标

- 不修改 `usePipeline` 的业务职责或复制其业务状态。
- 不修改 Python/Rust 后端、Tauri bridge、WebSocket 事件格式或字段。
- 不引入可调尺寸面板、多窗口、复杂拖拽、命令面板或新的信息架构。
- 不重做 ResearchTree、指标计算、Diff 或文件数据的业务逻辑。
- 不增加深色主题切换；本轮只交付已确认的 A2.2 主题。
- 不以大面积插画、渐变、玻璃拟态或装饰动画构建品牌感。

## 4. 视觉系统

### 4.1 视觉概念

视觉语言定义为“科研编辑部”：墨绿书脊负责系统导航，暖白纸面负责研究与对话，浅灰绿台账负责运行摘要。朱红用于需要注意的研究节点，研究绿用于阶段与证据，铜金只用于当前会话的窄标记。

界面应像连续的研究工作台，而不是多张白色卡片漂浮在灰色背景上。

### 4.2 色彩 Token

| 角色 | 值 | 用途 |
|---|---|---|
| `--canvas` | `#F0EEE7` | 应用背景与区域间底色 |
| `--paper` | `#F7F5EF` | 中央研究画布与主内容面 |
| `--ink` | `#1D2925` | 主标题与正文 |
| `--ink-muted` | `#68736F` | 辅助文字 |
| `--spine` | `#34443E` | 窄幅左侧导航 |
| `--spine-active` | `#465A52` | 当前会话背景 |
| `--ledger` | `#E4E8E2` | 右侧研究台账 |
| `--rule` | `#BEC6C1` | 分隔线与输入边框 |
| `--research` | `#356F63` | 阶段、证据与数据趋势 |
| `--attention` | `#AD5143` | 错误与需要处理的状态 |
| `--marker` | `#D0A84A` | 当前会话的 2px 标记 |

颜色面积目标：暖白与浅灰约 78%，墨绿约 12%，文字与分隔线约 8%，研究绿、朱红与铜金合计不超过 2%。

### 4.3 字体

- Geist：操作控件、正文、说明和普通标题。
- Geist Mono：指标、预算、实验编号和代码。
- Noto Serif SC：本地打包，仅用于研究主标题和关键章节标题。
- 字重限制为 400、500、600、700。
- 不使用负字间距；正文、按钮和紧凑面板不使用展示级字号。

字体必须随 Tauri 应用本地交付，不能依赖在线 CDN。

### 4.4 几何与层级

- 大区域不使用浮动卡片圆角。
- 普通控件圆角为 4px；消息记录和结构化提案最多 6px；微标签最多 3px。
- 取消面板通用阴影，仅弹出层允许使用一层轻阴影。
- 层级主要依靠纸面色差、1px 分隔线、留白、字体和对齐关系。
- 不使用大面积渐变、玻璃拟态、发光边框、浮动卡片墙或 hover 上浮。

## 5. 布局架构

### 5.1 目标尺寸

- 主要验收尺寸：`1440x900`。
- 最低桌面尺寸：`1024x720`。
- 小于最低尺寸的浏览器使用纵向回退布局，保证内容和操作不重叠；移动端不是本轮主要产品形态。

### 5.2 桌面工作台

应用由五个连续区域组成：

1. 暖白 masthead：品牌、研究名称和简化任务状态。
2. 墨绿会话书脊：约 176px，承载研究会话与新建操作。
3. 中央研究画布：自适应宽度，承载阶段、对话和输入。
4. 右侧研究台账：约 240px，承载摘要数据与详情入口。
5. 详情工作台：打开时占据中央与右栏下半部分，左侧书脊保持贯穿。

详情关闭时返回 `null`，不渲染“详情已收起”占位条。详情展开高度使用 `clamp(280px, 38vh, 420px)`，内容区自行滚动，不推动整个应用产生不可控的页面滚动。

### 5.3 响应式规则

- 宽屏保持 `176px / minmax(0, 1fr) / 240px`。
- 接近 `1024px` 时将书脊压缩至约 148px、台账压缩至约 210px，并缩小区域内边距。
- 低于桌面最小宽度时，导航转为顶部区域，研究台账排到会话之后。
- 固定格式的阶段条、图表和工具栏使用稳定网格或尺寸约束，动态内容不能改变整体轨道。

## 6. 组件设计

### 6.1 顶层边界

`AppShell` 只负责布局，通过插槽接收以下区域：

- `ResearchMasthead`
- `SessionSidebar`
- `ConversationPane`
- `RightRail`
- `ContextSurface`

`App` 继续从 `usePipeline` 获取 `viewModel` 和操作回调，再将所需数据传给各展示组件。布局组件不读取后端或调用 bridge。

### 6.2 ResearchMasthead

- 显示 Athena 品牌、当前研究名称和四态任务状态。
- 顶栏使用暖白纸面和底部分隔线，不使用大面积墨绿。
- 状态只显示一次，避免在各区域重复徽章。
- 当前 ViewModel 没有可靠连接状态，因此不显示连接灯或推断离线状态。

### 6.3 SessionSidebar

- 使用墨绿书脊背景。
- 当前会话使用浅一级墨绿和 2px 铜金标记。
- 会话标题单行截断，同时保留完整的可访问名称和 tooltip。
- 新建研究使用 Lucide 图标按钮与 tooltip。
- 不加入文件树、二级工具栏或额外仪表内容。

### 6.4 ConversationPane

- 标题区显示研究标题、简短说明和四阶段进度。
- 阶段只区分已完成、当前和未开始。
- Athena 普通输出呈现为研究记录，不再统一使用灰色气泡。
- 用户消息使用轻微朱红纸条底色并右对齐。
- `IntentPreviewCard` 改为结构化研究提案，展示任务类型、主指标、配置要求和启动操作。
- `ErrorCard` 使用朱红左侧线条、简短原因和明确操作；完整日志进入详情工作台。
- 输入区为稳定横向编辑面，发送按钮使用 Lucide 图标，并包含可访问名称与 tooltip。

### 6.5 RightRail

- 取消四张重复摘要卡，改为连续台账和分隔行。
- 严格使用现有 `RightRailSummary` 字段，按顺序展示：当前阶段与状态、最佳指标、剩余预算、最近实验和无提升轮次。
- 数值使用 Geist Mono 与制表数字。
- 每个可交互行继续调用现有 `openPanel(panel)`。
- 台账中的状态只出现在首行，其他数据不增加状态徽章。
- 本轮不展示虚构的小型趋势图或实验总数；只有后端协议未来提供真实序列后才增加趋势可视化。

### 6.6 ContextSurface

- 关闭时不渲染。
- 打开时显示标签页：研究树、指标、实验日志、差异、文件、报告。
- `contextSurface.activePanel` 继续作为唯一活动面板状态。
- 标签页切换复用 `openPanel(panel)`，关闭复用 `closePanel()`。
- ResearchTree、指标和 Diff 使用完整可用宽度，不嵌套进装饰性卡片。
- 关闭后将焦点返回到打开详情的入口。

### 6.7 图标

统一使用 `lucide-react`，不手绘 SVG。只有明确命令使用文字按钮；发送、关闭、新建和面板工具优先使用熟悉图标，并为不熟悉图标提供 tooltip。

## 7. 数据与状态

### 7.1 数据流

- `usePipeline` 继续负责消息、phase、status、预算、最佳结果和详情面板状态。
- 展示组件只消费 `PipelineViewModel` 或更窄的展示 props。
- 新增纯函数展示映射层，将后端状态与 phase 转为简洁中文标签、阶段序号和语义色。
- 不在组件中复制业务状态。
- 输入内容、tooltip、局部展开和焦点引用可以作为短暂 UI 状态留在组件内。

### 7.2 四种用户可见状态

| `PipelineStatus` | 用户可见状态 | 含义 |
|---|---|---|
| `idle` | 就绪 | 可以输入或启动任务 |
| `running` | 运行中 | 覆盖加载、流式输出、搜索与验证 |
| `completed` | 已完成 | 结果和报告可查看 |
| `paused`、`error` | 需要处理 | 用户需要恢复、确认或处理错误 |

四态状态只在 masthead 和台账首行出现。全界面最多保留一个活动动画，用于当前运行阶段。

### 7.3 阶段映射

后端 phase 收敛为四个用户阶段：

- `PREPARE`、`DATA_ANALYSIS` -> 数据理解
- `IDEA_GENERATION` -> 创意生成
- `SEARCH`、`CODE_GENERATION`、`EVALUATE` -> 假设筛选
- `VALIDATE`、`REPORT` -> 验证报告

未知非空 phase 显示为“研究进行中”，不直接暴露内部枚举，也不错误高亮四阶段中的任何一项。已完成阶段使用研究绿，当前阶段使用朱红或主文字强调，未开始阶段使用中性分隔线。

### 7.4 内容状态

- 空白会话：显示简洁起始内容，输入区仍为视觉焦点，不增加第五种状态。
- 加载数据：保留稳定布局，未知数值统一显示 `--`，不增加骨架动画。
- 流式输出：归入“运行中”，只在当前记录显示克制活动标记。

## 8. 错误处理

- 错误在会话流中保留一条可追溯记录。
- 台账首行同步显示“需要处理”。
- 默认错误内容只包含一句原因和一个明确操作。
- 完整日志通过实验日志详情查看。
- 不因普通错误自动打开详情工作台，避免打断当前阅读。
- 普通成功不使用大面积绿色反馈。

## 9. 可访问性与动效

- 使用正确的 `header`、`nav`、`main`、`aside`、`button` 与标题层级。
- 所有图标按钮具有 accessible name 和 tooltip。
- 键盘可以发送、打开台账详情、切换详情标签和关闭详情。
- `:focus-visible` 在纸面与墨绿区域都具有 WCAG AA 可见度。
- 正文、辅助文字和语义色达到 WCAG AA 对比度。
- 动效限于 120-180ms 的淡入、颜色和面板尺寸过渡。
- `prefers-reduced-motion` 下关闭非必要过渡。

## 10. 测试与验收

### 10.1 自动测试

- 为状态映射和阶段映射增加纯函数单元测试。
- 更新 `AppShell`、`ConversationPane`、`RightRail` 和 `ContextSurface` 测试。
- 验证四种用户状态、错误、空白、运行中和完成状态。
- 验证台账入口与详情标签仍调用现有 `openPanel(panel)`。
- 验证详情关闭和焦点恢复。
- 运行 `npm test` 与 `npm run build`。

### 10.2 视觉验证

- 在 `1440x900` 与 `1024x720` 运行浏览器截图检查。
- 检查控制台错误、横向溢出、文本截断、布局跳动和交互遮挡。
- 验证中央研究画布始终是视觉中心。
- 验证墨绿面积没有重新扩大为深色主题。
- 验证台账是连续信息面而非卡片墙。
- 验证详情内容具有足够空间，研究树和图表不被装饰容器压缩。

### 10.3 基线

设计确认时，`npm run build` 成功。实施必须保持构建通过，并在现有工作区改动上增量工作，不回滚用户已有修改。

## 12. 完成标准

- A2.2「窄墨书脊」在目标尺寸中准确落地。
- 四态状态模型完整替代分散的可见状态标签。
- 现有 pipeline、面板入口与后端行为保持一致。
- 键盘、焦点、错误、空白、加载和 reduced-motion 状态可用。
- 自动测试与生产构建通过。
- 目标尺寸截图中不存在重叠、溢出、截断、卡片墙或大面积深色回退。
