①分层总览

Athena 采用“渐进归一的模块化单体”。一个概念只有一个事实源；兼容模块只能重导出；Agent 负责不确定推理，而生命周期、预算、执行、比较与持久化由确定性服务负责。下方自顶向下：客户端 → 适配层 → 研究运行时 → 工作流 → Agent → 执行与事实平面。

▸ 分层边界（目标架构）：Research control = athena.research.ResearchRuntime；Policy = Supervisor + experiment.ranking + research.budget；Execution = CodeAgent + GitWorkBranch + protected evaluator；Facts = core.research_tree.ResearchTree v2 + core.contracts.ArtifactRef；Thread control = athena.app_server（保持独立，不承载研究状态）；Adapters = gui_gateway + Tauri + React。

②客户端与接入层

三层接入：Tauri + React 桌面 GUI（athena-gui）→ Tauri Rust 命令桥（PythonBridge） → gui_gateway WebSocket 传输 → 共享 ResearchRuntime。另有进程内 app_server 提供 Thread/Turn 协议栈。

2.1 端到端请求流

React 前端（Tauri webview）→ invoke("tree_get") [Tauri IPC] → Tauri Rust：PythonBridge.call("tree_get", {}) → WebSocket JSON {request_id, method, params} → gui_gateway 进程：WebSocketTransport.handle(ws) → handler.dispatch(method, params) → ResearchRuntime.dispatch() → ResearchTree.to_dict() → 响应回流（request_id 匹配）+ 事件通知经 Tauri 事件通道推送 → React usePipeline / useEvents 钩子合并事件 → 渲染树图 / 摘要卡

2.2 app_server：进程内协议栈

Transport（三通道复用两队列）

  • c2s：请求/通知/ServerRequestReply（Queue 64，背压 → OverloadedError）。
  • s2c_control：响应 / ServerRequest（Queue 64）。
  • s2c_event：事件通知（Queue 256），控制通道满不阻塞事件。
  • aclose() 向三队列发哨兵；_ready 屏障（处理后 initialized 才放行普通请求）。

MessageProcessor（状态机）

  • 状态：CREATED → INITIALIZING → READY → DRAINING → TERMINATED（+FAILED/FORCE_CLOSED）。
  • 控制方法（initialize/server/shutdown）内联；业务方法进待处理队列 → 信号量（≤64 并发）→ _execute_and_reply() → 响应。
  • 去重 request_id；request_approval() 发 ServerRequest 并挂 Future 等待客户端回复。
  • 非 READY 状态拒绝非控制请求（准入控制）。

ExecutionAdapter（无状态映射）

  • thread/start → manager.start()、turn/start → handle.submit()（立即返回）、turn/interrupt、thread/fork、thread/subscribe | unsubscribe。

事件系统 + 线程运行时

  • EventJournal：每线程 append-only 日志（asyncio.Condition）。
  • FairMux：轮询订阅多路复用，每周期每订阅至多投递一个事件。
  • RuntimeThreadManager：进程级注册表，封装 runner + ContextManager/Compactor/RolloutRecorder。
  • ThreadRuntime：每线程严格单 Turn 串行；submission_loop() 模式匹配 Submission / RuntimeSignal；maybe_compact() 前、record_items() 后、失败 rollback()；ThreadExecutionObserver 映射执行观测。
▸ app_server 与研究运行时互不承载：app-server 只处理 Thread/Turn 协议、订阅与并发控制；研究树、预算、任务元数据、验证与报告全在 athena.research.ResearchRuntime。

2.3 gui_gateway（纯转发）

构件职责
GuiRequestHandler持有 ResearchRuntime 引用；ping → {pong:true} 短路，其余全部委托 runtime.dispatch()。不持有会话/线程/连接/持久化状态。
WebSocketTransport每连接：订阅 → 循环读 JSON → 校验 RequestEnvelope → 分派 → 回 ResponseEnvelope；异常映射 rpc_error；finally 退订。serve(host, port=0) 用 websockets.asyncio。
逐连接订阅连接建立即 runtime.subscribe(emit_event)（research:{uuid}）；断开时 unsubscribe() 清理。
启动__main__ 打印 WebSocket 端口到 stdout 第 1 行；Tauri 读取该行发现端口。

③研究运行时与工作流

研究生命周期的唯一 owner 是 athena.research.ResearchRuntime。它持有全部研究状态，对外暴露类似 JSON-RPC 的 dispatch(method, params) 应用命令，并编排 PREPARE → SEARCH → VALIDATE → REPORT 四阶段链。

3.1 ResearchRuntime 状态与命令

拥有状态

  • _tree: ResearchTree — 实验 DAG 事实源
  • _phase: ResearchPhase — IDLE/CONFIGURED/PREPARE/SEARCH/PAUSED/VALIDATE/REPORT/COMPLETED/FAILED/CANCELLED
  • _active_task: TaskMetaData — 已配置任务（task_type/data_type/primary_metric）
  • _budget: BudgetSnapshot — 剩余实验配额 + 连续无改进追踪
  • _run_task: asyncio.Task — 当前后台搜索任务
  • _resume_gate: asyncio.Event — 协作式暂停门（PAUSED 清除、SEARCH 设置）
  • _subscribers: dict[str, EmitFn] — 事件订阅者，失败自动移除
  • _save_path — 默认持久化 .athena/research_tree.json
  • _dependencies: ResearchWorkflowDependencies — 可插拔后端（prepare_baseline / search_factory / validator / reporter）

公开应用命令（ResearchMethod）

命令行为
PARSE_INTENT从自然语言猜测任务配置，返回 needs_configuration=True 草稿
TASK_CONFIGURE构造 TaskMetaData，阶段 → CONFIGURED
SEARCH_START校验依赖；无 baseline 时先进入 PREPARE；初始化预算
SEARCH_PAUSE/RESUME/STOP门控 / 取消搜索循环
VALIDATE_START找成功 SOTA，调 validator 运行消融与 final-test
REPORT_GENERATE由树内证据生成确定性 Markdown 报告
TREE_GET / SAVE / LOAD树快照获取、原子保存、严格 v2 加载

3.2 四阶段工作流

PREPARE · workflows/prepare/
create_baseline()：要求 train/val/test 拆分 → 代理起草 BaselineDraft → 在树中登记假设与 kind="baseline" 实验 → 在分支 baseline/{exp_id} 建 worktree（RUNNING）→ CodeAgent 运行 run_experiment.py（5min）+ eval.py（1min）→ 读 eval_result.json → 完成实验并 tree.set_sota() 建立初始 SOTA。失败阻断 SEARCH。
baseline.py · evaluator_factory.py · data_analysis.py · experiment/pipeline.py
SEARCH · workflows/search/search_loop.py
SearchLoop.run() 循环至预算耗尽或 Supervisor STOP：收集 pending 假设（复用或 Ideator 生成）→ ranker.select() 选择 → 从 SOTA 分支 worktree → CodeAgent 执行 → Comparator.compare() → Supervisor.decide() → 若 ACCEPT 且候选获胜则 tree.set_sota() → 更新假设状态与 ranker/proximity → budget.consume()。
search_loop.py · code_agent.py · idea_generation.py
VALIDATE · workflows/validate/ablation.py
Validator.run(sota_id, tree)：校验 SOTA 资格 → 遍历 hypotheses_path() → 为每个假设创建 kind="ablation" 子实验 → 运行一次 kind="final-test"（冻结 final 测试）。幂等：已 SUCCEEDED 则跳过；verdict=None（不改 SOTA）。
ablation.py
REPORT · workflows/report/final_report.py
Reporter.generate()：校验 SOTA + 全部消融成功 + 恰好一个成功的 final-test → 收集证据字典 → 生成 ReportNarrative（有代理则 LLM，否则默认文本）→ 写 athena_report_{sota[:8]}.md → 附到 SOTA。
final_report.py

3.3 策略：排序、监督与预算

HypothesisRanker（规范）实现

  • 确定性 Bradley-Terry 评分：成对比较增量更新（step=0.1，sigmoid gap）。
  • 选择用 UCB 探索-利用：mean + β·uncertainty − 0.1·(1−min_distance)；uncertainty 来自计数 + 64 次自举重采样（确定性种子）。
  • TODO(advanced-ranking)：未来 Elo 风格 rubric 需先批准 rubric / pair construction / cold start / confidence calibration。
athena/experiment/ranking.py

ProximityGraph

  • 词法 Jaccard 距离（statement + intervention 词袋）。
  • min_distance_to_executed() 抑制相似假设重复执行。
athena/experiment/ranking.py

Supervisor.decide(verdict, budget)

  • 预算耗尽 → STOP；候选获胜 → ACCEPT（最后改进也 ACCEPT）。
  • baseline 获胜：连续 no_improve_streak+1 ≥ max_no_improve → STOP，否则 REJECT。
  • 平局：临近耗尽 STOP，否则 REJECT。
  • 成为 SOTA 必须 ACCEPT 且 winner=candidate，且实验 SUCCEEDED、plan.kind ∈ {baseline, search}。
athena/experiment/supervisor.py

BudgetSnapshot（当前实现）

  • 字段：remaining（默认 20）、no_improve_streak（0）、max_no_improve（5）、is_exhausted。
  • consume(improved)：递减 remaining；improved 重置 streak，否则 +1。
  • RunMode(hil, debug)：人在回路 / 调试开关。
athena/research/budget.py

BudgetConfig（目标）迁移后

  • 不可变 BudgetConfig（frozen, extra=forbid）只表达上限。
  • 可变耗用改由 ResearchRuntime 内部 ledger 记录，与 checkpoint 一同持久化，幂等结算。

④Agent / 统一内核

代码库当前存在两套并行的 Agent 系统：core/agent/ 是活跃的生产实现，core/agent_kernel/ 是已裁可的下一代统一内核（迁移中，尚无外部消费者）。两者与 Ideator 的多 Agent 辩论、app_server 的 Thread/Turn 构成三层重叠，正是统一内核要收敛的动机。

5.2 实验隔离：LocalGitWorkspace

worktree 生命周期

  • init()：初始化仓库 + 初始提交（幂等，返回 HEAD）。
  • create(base_commit, branch)：worktree_root 下建 athena-<uuid> 独立 worktree；校验分支名；失败清理分支引用。
  • diff(workspace)：git add -A 生成含二进制完整 diff → 写入 ArtifactStore → 记录审查状态（SHA-256 / tree / HEAD）。
  • commit(workspace, approved_artifact, message)：校验审查工件与当前 diff 匹配、工作区未被改动，用 git commit-tree 原子提交；空 diff 复用 HEAD。
  • remove(workspace, delete_branch, force)：拒绝非干净移除，可 -D 删分支。
src/athena/git_workspace.py · core/workspace.py（GitWorkspace 契约）

隔离与锁

  • CodeAgent / Codex / Qoder 只修改自己的 worktree。
  • diff → Supervisor 审查 → 只接受最后一次生成的同一 diff_ref 提交。
  • 不同实验可并行；同一实验的 diff/commit 不会竞争（仓库锁 + 逐 worktree 锁）。
  • commit/remove 等不可回滚副作用在 Git 与树状态到达一致点后再传播。
▸ 真实评估证据：成功实验必须含有限 primary、逐样本证据与真实生命周期状态；失败必须带非空 error。代码执行失败不伪造零指标或候选胜出。

6.1 ResearchTree v2（core/research_tree.py）

内部结构

ResearchTree ├─ hypotheses: dict[hypothesis_id, Hypothesis] ├─ experiments: dict[experiment_id, Experiment] │ ├─ parent_id / hypothesis_id / commit │ ├─ plan: ExperimentPlan │ ├─ gitwork: GitWorkBranch │ ├─ status: PENDING|RUNNING|SUCCEEDED|FAILED|CANCELLED │ ├─ eval: EvalResult | None （仅成功可含） │ ├─ verdict: ComparisonVerdict | None │ ├─ artifacts: {kind: ArtifactRef} │ └─ error: str | None （失败必须非空） ├─ _children_index（派生，不持久化第二份关系源） └─ sota_id

关键方法与不变量

  • 实验不嵌入自己的 ID；ID 是 experiments 映射键；子关系仅由 parent_id 派生。
  • transition_experiment() 经 _ALLOWED_TRANSITIONS：PENDING→RUNNING / PENDING→CANCELLED / RUNNING→SUCCEEDED|FAILED|CANCELLED；终态不可变。
  • complete_experiment() 只接受 RUNNING，合并 eval/verdict/artifacts。
  • set_sota() 只接受 SUCCEEDED 且 plan.kind ∈ {baseline, search}；验证实验（ablation/final-test）不具 SOTA 资格。
  • hypotheses_path() 根到节点的完整假设链（供 Agent 恢复研究上下文）。
  • from_dict() 完整校验：键/类型/循环/父引用/SOTA 资格全通过后才替换活状态；版本非 2 明确报 schema 错。
  • save() 原子替换（写 .tmp → fsync → os.replace）。
▸ 真实证据不变量：任何成功记录不得使用 “N/A”、伪造零指标或缺失验证结果作为能力替代。代码执行失败不伪造零指标或候选胜出。

11.1 Ideator 辩论数据流

Ideator.generate(profile, papers, models, tree) ├─ 1) 序列化完整只读科学上下文 → context_ref（稳定 artifact 承载大对象） ├─ 2) 创建 N 个"ideator-debate" Thread（_DebateRunner 逐线程代理绑定） ├─ Stage 1 PROPOSE ：每辩者提议 3–5 个可证伪假设（需 ≥ quorum 成功） ├─ Stage 2 REVIEW ：每辩者匿名评审其他所有候选（alias 映射，retain/revise/reject） ├─ Stage 3 REVISION ：每辩者按收到评审修订自己的候选（key 完全一致） ├─ Stage 4 JUDGE ：唯一 judge Thread 读完整辩论记录（含失败与 lineage）→ _JudgeOutput │ 校验：decision keys 全覆盖候选、无遗漏/重复/未知；lineage 只引 selected/merged └─ 输出 DebateResult：hypotheses(3–5, 各含 evidence_refs→audit artifact) + transcript + failures + artifact_ref → generate_hypotheses() 登记到树 → SearchLoop 仅返回原样 hypotheses 列表
▸ 阶段失败显式记录在 failures 中并显式报错；不存在模板 fallback。Ideator 为唯一 IdeaGeneration 负责人。

⑭现状 / 目标差距
