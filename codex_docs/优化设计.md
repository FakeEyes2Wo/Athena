## 3. Plan 合同可以更粗、更简单

### 3.1 用冻结 Tree 引用和 ID 代替复制 Hypothesis 模型

当前 `PlanInput` 为了深层不可变，引入 `_FrozenHypothesis`、两个转换 validator，
并将 `Hypothesis` 内的 list 隐式转换成 tuple。这增加了一个与 ResearchTree 平行的
Hypothesis 表示，还改变了消费端看到的字段类型。

更简单的合同：

```python
class PlanInput(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid", strict=True)

    hypothesis_id: str | None = None
    active_hypothesis_ids: tuple[str, ...] = ()
    reference_experiment_id: str | None = None
    reference_metric: float | None = None
    reference_priority: float = 1000.0
    evaluator_ref: ArtifactRef
    tree_ref: ArtifactRef
    human_context: str = ""
```

`tree_ref` 已指向创建 Plan 时的不可变 ResearchTree artifact。ID 从该冻结快照解析，
既保留原始 statement/intervention/evidence，又无需复制和冻结另一个领域模型。
Plan 恢复时只允许读取 `tree_ref`，不得回读更新后的全局 Tree。

这项修改应在 Task 5 开始消费 `PlanInput` 之前完成。验收测试只需证明：

- 后续修改全局 ResearchTree 不改变通过 `tree_ref` 解析出的 Plan 上下文；
- JSON round trip 保留 ID 顺序；
- 未知 hypothesis ID 在创建 Plan 时失败。

### 3.2 不要为了省三个 JSON 字段增加自定义序列化协议

当前 `PlanState` 使用 `model_fields_set` 和 wrap `model_serializer`，只为让 PREPARE
和 VALIDATE 的 JSON 不出现 `patience/stale_rounds/best_ref`。这三个 null/default
字段的空间成本可以忽略，但自定义序列化会影响 `model_dump`、嵌套序列化和恢复
行为，测试成本明显更高。

建议允许所有 PlanState 使用同一稳定 JSON 形状：

```python
class PlanState(BaseModel):
    kind: Literal["PREPARE", "SEARCH", "VALIDATE"]
    context_ref: ArtifactRef
    turns_used: int
    turn_limit: int | None
    patience: int | None = None
    stale_rounds: int = 0
    best_ref: ArtifactRef | None = None
```

保留一个 validator：SEARCH 必须有 patience；非 SEARCH 的三个字段必须保持默认值。
删除 `model_serializer` 和基于“字段是否显式传入”的语义。技术设计中“omit”应改为
“must stay at defaults”，换取单一、直接、可观察的持久化合同。

### 3.3 ArtifactRef 格式校验只应有一个所有者

当前 `ArtifactRef` 在 core 中仅保证非空，Plan 合同又逐字段调用
`digest_from_ref`。后续 manifest、validation、events 很容易重复同样的 validator。

在 Task 5 前先用 `rg` 审计所有 ArtifactStore producer：

- 如果所有持久 artifact 都是 `sha256:<64 hex>`，就在 core 收紧 ArtifactRef 类型，
  删除 Plan 内逐字段 validator；
- 如果仍有合法的非 SHA 引用，保留宽泛 ArtifactRef，并新增一个语义明确的
  `ContentArtifactRef` 作为共享类型；
- 不允许每个 Supervisor 模型各自复制 `digest_from_ref` validator。

## 4. Hypothesis 只保存研究事实，PlanState 保存执行现场

当前 Hypothesis 同时存在旧字段 `patience_grant/patience_evidence_ref` 和新字段
`patience/turn_limit`；PlanInput 又保存 `initial_patience/initial_turn_limit`，PlanState
再次保存有效预算。这是三套预算表达。

建议收紧为：

- Hypothesis：保留 SupervisorAgent 建议并最终结算的 `patience/turn_limit`，作为
  永久研究决策；删除无活跃消费者的旧 `patience_grant/patience_evidence_ref`。
- PlanInput：通过冻结 Tree 的 Hypothesis ID 获得初始预算，不再复制 `initial_*`。
- PlanState：只保存运行中的有效 `turn_limit/patience`、已用 turns、stale rounds 和
  best ref；Human 对单个 Plan 的调整只改这里。

这样永久研究事实、冻结输入和可变执行现场各有一个所有者。

## 5. ResearchTree 和 Elo 当前不应继续抽象

以下实现虽然不是理论上的最高性能，但在最多 10 次 Search 的边界内更易理解：

- `experiment_for_hypothesis` 线性扫描；
- `add_hypothesis` 用 `max(order) + 1` 分配 FIFO；
- `active_hypotheses` 每次沿父链计算继承集合。

不要新增 experiment index、通用图层或 policy registry。只有真实 trace 证明调度
成为瓶颈后再优化。`HypothesisPolicy` Protocol 是用户明确要求的替换边界，可以
保留；首版只允许 `EloPolicy` 一个实现。

一个可做的局部简化是将 Elo 结果表提为常量：

```python
_OUTCOME_SCORE = {Outcome.WIN: 1.0, Outcome.DRAW: 0.5, Outcome.LOSS: 0.0}
```

但收益很小，不应单独产生提交。

## 6. Git workspace 状态应从无类型 dict 收紧

`LocalGitWorkspace._states` 当前保存嵌套 dict，并通过 `"workspace"`、`"review"`、
`"committed"`、`"artifact"`、`"tree"`、`"head"` 等字符串跨方法传递状态。
多轮 checkpoint 已让这个结构成为真实状态机，继续使用 dict 会增加拼写和
非法组合风险。

建议仅在 Task 4 证据校准时做一次局部替换，不增加公共接口：

```python
@dataclass
class _Review:
    artifact: ArtifactRef
    digest: str
    tree: str
    head: CommitHash
    empty: bool

@dataclass
class _WorkspaceState:
    workspace: GitWorkBranch
    review: _Review | None = None
    committed: tuple[ArtifactRef, CommitHash] | None = None
```

它们保持模块私有；`GitWorkspace` 公共合同不变。不要进一步创建 WorkspaceManager、
Repository 或 checkpoint service。

### Task 5 提交前收紧建议

#### 1. ExecutionRuntime 的 command/argv 必须二选一

当前兼容签名允许 `command=None, argv=None`，也允许两者同时传入。把非法状态推入
执行器会让错误位置变晚。保留一个方法即可，但入口应立即验证 XOR：

```python
if (command is None) == (argv is None):
    raise ValueError("exactly one of command or argv is required")
```

`CommandExecutor.run` 不应再次复制同一判断；它只消费已经规范化的调用。增加两项
测试：都缺失、同时提供均在创建 subprocess 前失败。

#### 2. 失败结果不要伪造 stale_rounds=0

`PlanTurnResult.stale_rounds` 当前默认 0。执行/输出/评分失败时，设计要求 patience
完全不变，但调用者若直接用结果更新 PlanState，会把原来的 2 错误重置成 0。

更小且不歧义的合同是：

```python
class PlanTurnResult(BaseModel):
    kind: Literal[...]
    next_state: PlanState | None = None
    metric: float | None = None
    commit: CommitHash | None = None
    predictions_ref: ArtifactRef | None = None
    evidence_ref: ArtifactRef | None = None
    error: str | None = None
```

只有可信评分返回 `next_state`；所有失败返回 `None`，Supervisor 保留原 state。
如果暂不采用 `next_state`，至少把 `stale_rounds/best_ref` 改为 optional，并禁止
失败结果携带它们。

#### 3. 不要再定义第二个 Decision

`plans.py` 已拥有 `PlanDecision.decision: continue|submit|abandon`。`experiment.py`
重新定义 `Decision = Literal[...]` 会让两个模块共同拥有同一协议。让
`decide_settlement` 接受 `PlanDecision`，或在 `plans.py` 暴露唯一的
`PlanDecisionKind` type alias；不要在 experiment 中复制字面量。

#### 4. Manifest 错误应保留可行动细节

`read_experiment_manifest()` 把所有 JSON/Pydantic 错误压成 `None`，最终只返回
`experiment.json missing or invalid`。PlanAgent 无法知道是 shell string、路径逃逸
还是缺 predictions。保持一个失败类型即可，但 `error` 应包含经过截断/清理的
ValidationError 信息，供同一 Plan 修复；这不需要异常类层级。

#### 5. 不捕获所有 evaluator 异常为候选错误

技术设计区分“候选输出导致评分失败”和“Evaluator 基础设施失败”。当前
`except Exception` 将二者都归为 `scoring_failed`，可能让 Agent 反复改代码而实际是
运行环境故障。优先复用 TrustedEvaluator/DataScriptRunner 已有异常分类；若当前无
分类，只增加一个最窄的 adapter，不创建第二个 evaluator。
